## 핵심 결론
1. 지원형 몬스터는 **소환형과 회복형 두 종으로 분리**한다. 소환형은 안전한 위치를 찾아 뿌리내린 후 움직이지 않고 계속 몬스터를 소환하며 자신은 공격하지 않는 방향이다. [10:31–14:51]
2. 터렛이 추적하지 못하는 대상은 우선 **암살자**로 정한다. 반투명 표현과 업그레이드에 따른 탐지 기능은 추가 검토 사항이다. [17:48–18:57]
3. 탄환 분열 방벽은 **시험 제작 후 재미를 보고 판단할 아이디어**다. 정식 채택이나 터렛 탄환 API 추가를 확정한 것은 아니다. [15:02–17:45]
4. 수리 검증을 위해 황재동이 파괴된 터렛과 체력이 감소한 터렛을 각각 배치한다. Core 검증 지원과 Enemy·Level Docs 갱신도 요청됐다. [21:44–22:40, 32:24–32:38]

## 안건별 상세
### 1. 지원형 몬스터 역할 분리 [02:27–14:51]
- 초반에는 소환 시설 설치와 회복을 한 몬스터에 묶는 방식, 시설로 변환하는 방식 등을 비교했다. 에셋과 구현 시간도 논의했다.
- 황재동은 돌아다니며 씨를 뿌리는 컨셉을 제안했다. 중간의 복합형·상태 전환 의견보다 **후반의 두 종 분리 결론**을 기준으로 정리한다.
- 소환형: 이동해 안전한 곳을 찾은 뒤 고정되어 소환을 지속한다. 뿌리내린 뒤에는 움직이지 않는 방향이며 수기에도 자신은 공격하지 않는다고 적혀 있다. 안전 위치 판정 알고리즘은 확정되지 않았다.
- 회복형: 별도 몬스터로 구성한다. 조수빈이 힐 구체 발사와 착탄 후 범위 회복 등을 예로 들었고, 구체적인 회복 방식은 만들어본 뒤 공유하기로 했다. 시설형·직접형 중 세부 구현을 확정했다고 기록하지 않는다.

### 2. 탄환 분열 방벽 [15:02–17:45]
- 이영빈이 플레이어 또는 터렛 탄환이 장벽을 통과하면 분열하는 스킬 아이디어를 설명했다.
- 일단 만들어보고 피드백을 받아 재미가 없으면 제거하는 방식으로 접근한다. 배수나 최종 효과 수치는 정하지 않았다.
- 수기에는 채택 시 터렛 탄환 API가 필요하다고 적혀 있다. **조건부 연동 과제**로 유지한다.

### 3. 터렛 비탐지 몬스터 [10:58–11:39, 17:48–18:57]
- 우선 암살자를 터렛이 추적하지 못하는 대상으로 삼는다.
- 반투명 표현 정도는 검토한다. 완전 투명 여부나 구체적인 알파 값은 미정이다.
- 조수빈의 탐지 업그레이드 제안과 황재동의 유사 게임 사례는 설계 후보로 남긴다. 전 터렛 적용 정책이나 구현 완료를 뜻하지 않는다.

## 분야별 진행 보고
### Turret — 황재동 [19:17–25:05]
- 밸런스 표를 작성해 공유 폴더에 올렸다. **현재 게임 수치 정리본이며 최종 밸런스 확정값이 아니다.**
- 파괴 후 일부 전력 반환·손실률 작업은 PR이 열려 있고 당시 아직 리뷰가 없다고 보고했다. 완료·병합으로 처리하지 않는다.
- Core 쪽에 터렛 검증을 위한 메서드·지원 작업을 요청했다. 회의에서 개별 목록과 완료 기한은 확정하지 않았다.
- 이영빈의 수리 검증 요청을 받아 파괴된 터렛과 체력 감소 터렛을 각각 배치하기로 했다.
- 터렛 상태에 따른 Enemy 공격 허용 여부는 공통 타기팅 가능 여부 값과 연결하는 방향을 확인했다. 정확한 API 식별자는 자동 인식이 불명확하므로 저장소 확인 전 확정하지 않는다.

### Player — 이영빈 [21:56–22:40, 25:15–26:40, 28:29]
- 수리 검증용 터렛 두 상태가 필요하다.
- 팔·총·손의 앞뒤 표현 및 스프라이트 분리가 다른 작업을 지연시키고 있다. 비주얼 작업을 잠시 미루고 기술 작업을 우선 진행한다.
- Enemy가 제기한 피해 처리 공통화에 대해 Player 쪽 HP 관련 구조를 준비하겠다고 답했다. 구체적인 인터페이스·변경 범위는 후속 확인이 필요하다.

### Enemy — 조수빈 [22:52–24:50, 26:53–29:22]
- `Prefabs/Enemies/Runtime` 아래 런타임 프리팹을 사용해 달라고 안내했다. 근접형은 그 아래 근접형 분류 안에 있다. 상위 프리팹이나 오래된 경로를 임의로 사용하지 않도록 한다.
- 1스테이지 근접형·폭발형과 원거리 기반 및 캐논 슬라임 구현을 보고했다. 다른 원거리형은 이를 기반으로 확장할 계획이다.
- 터렛과 Player의 피해 수신 구조가 달라 공격 측에서 분기해야 하므로 공통 구조로 맞추자고 요청했다. Player 쪽에서 기존 터렛 구조를 확인하기로 한 흐름이다. 코드 통합 완료로 기록하지 않는다.
- 지원형 두 종 구현 및 회복 방식 시안 공유가 후속 작업이다.

### Level — 김진태 [29:37–31:04]
- Core 관련 PR 검토가 거의 끝나 회의 당일 또는 다음 날 구현을 시작할 수 있을 것으로 보고했다. 이는 예상이며 확정 완료일이 아니다.
- Enemy 관련 문서를 요청했고 확인에 시간이 필요하다. 날씨 변화와 Enemy 스폰·날씨 이벤트 연동도 작업 범위에 포함된다.

### Core — 양현석 [31:11–32:18]
- Steam API 조사 및 구현 설계를 준비 중이다.
- 부팅 → 메인 → 게임 진입의 한 사이클을 이번 주 안에 구성할 계획이다.
- 김진태와 Weather·Time 연동 및 마무리를 진행한다. 구현 완료로 단정하지 않는다.
- 안전장치인 Save 시스템 구현을 시작했으며 아직 완성되지 않았다.
