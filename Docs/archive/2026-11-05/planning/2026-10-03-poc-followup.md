## 일정·가용 시간

- 시험 기간에는 김진태·조수빈의 개발량을 줄이고 회의를 간단한 진행 공유로 운영한다. 김진태는 스터디·회의에 참여하고 조수빈은 스터디를 쉬되 회의에 참여하는 방향이다. 시험 날짜로 10월 20–26일과 16–26일이 각각 언급되어 팀 전체 적용 기간으로 확정하지 않는다. 다음 마일스톤은 PoC 통과 후 재검토한다.
- 팀 모임은 10월 29일을 우선 일정으로 잡고 수원 방향을 언급했다. 시간·식당·주소·예약은 미확인이다.

## 후속 작업과 미결정

- 실제 Build에서 전선의 형성·유지·가시성, 터렛 배치 밀도와 몬스터 충돌·끼임을 기록한다. 녹음의 주말 마무리 계획을 완료 선언으로 바꾸지 않는다.
- 조수빈과 몬스터 종류별 타깃 특성·분대 프리셋을 구체화한다. 일회성 추격 판단은 제안이며, 이전 [10월 2일 AI 구조 검토](https://github.com/Team-HJD-21/unity-6-the-developer/blob/1a03e9a9164e5db94cbc8775162467d08cf63a3b/Docs/planning/2026-10-02-ai-architecture-review.md)의 상위·분대·개체 계층을 확정한 뜻은 아니다.
- Player 직접 공격 비중, 스킬·무기·몬스터 사이의 대응 관계를 검토한다. 미니 터렛, 임시 강화, 드론, 빙결 등은 아이디어이고 수치·구현 범위가 정해지지 않았다.
- 터렛 API 사용법을 Docs에 제공하고 Markdown 내려받기를 검토한다. 관련 문서 PR이 실제로 병합되기 전에는 게시 완료로 표시하지 않는다.
- 지역 해금·코어 연결과 안전장치 저장 필드를 관련 영역에서 조율한다. 이 문서의 **안전장치 상태 스냅샷**은 [터렛 API의 읽기 전용 `TurretSnapshot`](https://github.com/Team-HJD-21/unity-6-the-developer/blob/1a03e9a9164e5db94cbc8775162467d08cf63a3b/Docs/architecture/turret-system-guide.md)과 목적이 다르며, 동일한 저장 형식으로 확정하지 않았다.
- 우주선 내부 에셋은 제작을 먼저 시도하고 필요할 때 구매를 다시 판단한다. 16×16은 제작 요청 기준이며 구매·라이선스 확인이나 완료의 증거는 아니다.
