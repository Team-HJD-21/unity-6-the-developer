# 2026-11-13 HUD 피드백·텍스트 Alert 리뷰

사용자 추가 피드백의 구현·검증 기록이다. 최종 미감 승인은 실제 화면을 함께 본 뒤 확인한다. 공통 기준은 [공통 UI 규칙](common-ui-rules.md), 송출 계약은 [공통 Alert API](../02_architecture/03_scene-flow/common-alert-api.md)를 따른다. 앞선 [메인·설정·메뉴·로딩 리뷰](ui-review-2026-11-13.md)와 [실제 입력 검수의 범위](ui-pointer-review-2026-11-13.md)는 별도로 보존한다.

## 반영

| 요청 | 구현 |
| --- | --- |
| Q/E와 바늘 겹침 | 원 중심에서 회전하는 가는 기계식 바늘 몸체에 불투명 원형 Q/E 배지를 결합했다. Q/E 반지름은 100/142, 지름은 36이며 글자는 정방향이다. 두 바늘을 모두 그린 뒤 배지를 그려 교차 선이 글자를 관통하지 않는다. |
| Alert 템플릿 | 배경·테두리·아이콘·장식선을 제거하고 기존 본문 폰트의 중앙 정렬 글자만 표시한다. 오류 빨강·성공 초록·정보 금색과 얇은 어두운 외곽선을 사용한다. 스킬 바로 위에 놓고 반원·설명·드래그 디스크와 실제로 겹치면 그 위로 비킨다. 포인터 입력을 막지 않는다. |
| 송출 정리 | App 수명의 `AlertService`와 `GameAlerts.Show`로 미배정 Q/E, 실제 설치 확정 실패, 터렛/CU 명령 결과, 공용 디버그 결과를 연결했다. 지속적인 거리·냉각·처리 상태는 해당 패널에 남긴다. 설치 미리보기 매 프레임에는 송출하지 않는다. |
| 반복 입력 | 현재/대기 중 같은 키는 중복 등록하지 않으며 표시 시간을 연장하지 않는다. 대기는 최대 3개다. 로딩·전체 씬 전환·결과 화면에서 현재와 대기를 정리한다. |
| 슬롯 쿨타임·누름 | Q/E/SPACE 카드 전체를 Filled로 덮는다. 모서리는 카드 윤곽의 UGUI 마스크로 잘라 프레임 밖 사각형이 생기지 않게 했다. 실제 입력에는 짧은 축소·틴트 후 smoothstep 복귀를 넣었다. |
| 상단 | 화면 상단에 붙은 반투명 역 사다리꼴 바탕. 실제 공용 시계의 마지막 5~0초에는 타이머만 빨강과 1.12→1 크기 펄스를 적용한다. phase 전환·미확정 시간에는 정상 상태로 돌아간다. |
| HP 피격 | Player/CU의 같은 최대 HP에서 실제 HP가 줄었을 때만 짧은 흔들림·밝기·감소 잔상이 나타난다. 최초 연결·최대값 변경·전력 소모는 피격으로 처리하지 않는다. |
| 드래그 전 호버 | 원본 스킬 이미지가 조금 들리고 희미한 원위치 그림자와 작은 집기 패턴으로 이동 가능성을 암시한다. 조작 설명 문장은 추가하지 않는다. 드래그 시작 순간 호버 반응을 정리하고 디스크 설명 하나만 유지한다. |

바늘·배지·상단 판·쿨타임 마스크·집기 패턴은 기존 UGUI 안에서 편집 가능한 `CombatHudShape`로 제작했다. 새 외부 디자인 에셋이나 라이브러리를 추가하지 않았다. 두 HUD 프리팹과 공용 Alert 프리팹의 연결을 저장했으며 실행 중 UI 계층을 새로 제작하지 않는다.

`CombatHudAlertLayout`은 화면 픽셀 좌표를 사용한다. 접힌 스킬의 원래 상단을 최소 경계로 유지하고 보이는 반원, 설명, 디스크·금지/대상 배지의 사각형 중 실제 겹치는 것만 피한다. HUD 해제·우주선·비활성화에서는 예약 경계를 초기화한다. 원형 UI나 게임 판정은 변경하지 않는다.

반복 제작 시 HP 감소 잔상이 정상 HP 위에 올라오던 순서도 수정했다. 잔상/원본과 호버 그림자/원본 그림의 그리기 순서는 제작 도구를 연속 실행해도 유지한다.

## 실제 Scene·화면 검수

1920×1080 Game View, 사용자의 현재 HUD 설정 75%로 확인했다. 화면은 생성 이미지가 아닌 실제 렌더 PNG이며 게임 시간은 가속하지 않았다.

- **OS 마우스:** 실제 Play 버튼, 하단 접근, 터렛 호버 시 이미지 들림/집기 패턴/설명, 배치 불가 지점 클릭과 빨간 텍스트 Alert를 확인했다. 배치 준비만 기존 Player API로 수행했고 확정 클릭은 CUA가 보낸 실제 OS 입력이다. 이때 가상 입력장치는 없었다.
- **정상 프레임 InputSystem:** 누름→이동→놓음을 다른 프레임으로 전달한 드래그에서 디스크·금지/대상 예고·장착/교환/취소를 확인했다. 물리 OS 드래그와 구분한다. Q/E 배지 사이 최소 거리 48.06으로 지름 36보다 컸다.
- **최종 텍스트 알림:** 기본 59프레임, 실제 호버 유지 60프레임, 실제 OS 배치 실패 148프레임, 정상 프레임 드래그 99프레임을 기록했다. 알림 표시 표본 **203개에서 스킬·선택 설명·디스크와 사각형 겹침 0**. 호버/드래그의 배치 검수용 알림은 `GameAlerts.Show`로 송출했으며 실제 게임 실패 발생으로 표시하지 않는다.
- **피격:** 실제 피해 API로 Player 400→320, CU 1500→1200을 적용했다. 45프레임에서 HP 1→0.8, 잔상 hold 후 0.8 수렴, 흔들림 X 최대 4.56 후 0 복귀를 관측했다. 초기 연결과 회복된 정상 HP의 색도 확인했다.
- **실제 시계:** Day 300초가 지나기를 기다려 마지막 5~1초를 99프레임 기록했다. 빨간색과 1~1.12 펄스, 이후 Night 정상색 복귀를 확인했다. 0초는 phase 전환이 즉시 일어나며 별도 경계 검사에서도 다룬다.
- **수정 후 실제 귀환:** Initial_Stage 필드에서 생성된 메뉴의 실제 `Secondary.onClick` callback으로 Hub에 Single 복귀했다. OS 클릭 재검수와 구분한다. Hub 1개/Player 1개/활성 카메라 1개/필드 HUD 0개, Alert alpha 0, 입력 잠금 해제를 확인했다. 915×780 Free Aspect의 우주선 메뉴 화면도 직접 열어 확인했고, 우주선 복귀 버튼은 숨김·Continue는 활성 상태였다. Continue callback 뒤 메뉴와 입력 lease가 함께 해제됐다.

Windows 컴퓨터 유즈의 키 입력/누른 채 이동 전달 제한은 기존 입력 검수 기록에 보존했다. 이번 결과를 OS 키보드·누른 채 드래그까지 통과한 것으로 확대하지 않는다. 해당 동작은 정상 프레임 InputSystem과 실제 EventSystem 경로로 확인했다.

최종 화면·모션 재생본은 로컬 아티팩트 `hud-feedback-review-20261113/index.html`에 제공한다. 중간 Alert 패널 시안이나 수정 전 주황 HP가 섞인 녹화는 최종본에서 제외했다. HTML의 실제 PNG 참조와 JavaScript 구문을 검사했다. 내장 브라우저는 `file:` 열기를 보안 정책으로 거부해 브라우저 재생 동작은 새로 검증하지 않았고, 다른 전송 방식으로 우회하지 않았다. PNG 원본은 직접 열어 확인했다.

## 보존과 남은 확인

기존 메인 배경/로고와 사용자 NEXON SDF를 보존한다. 사용자가 Play 사용 중 변경한 Initial_Stage와 ThinMulmaru SDF를 새 기준으로 유지하며 이전 상태로 돌리지 않는다. 검사 중 변한 날씨 재질은 `_Blend` 외 내용이 기준과 같음을 확인한 뒤 해당 실행 변동만 복구한다. 최종 Editor는 Startup 편집 모드, Game View Free Aspect, 기존 75% 설정으로 복원한다.

최종 미감은 사용자 검토가 남았다. 실제 Standalone 빌드·원격 Client는 이번에 실행하지 않았다.

직접 Initial_Stage에서 메뉴로 우주선에 Single 복귀할 때 Hub 조립이 빠지던 별도 Core 경로도 수정했다. 기존 `GameFlow`가 없을 때만 기본 Hub 경로를 사용하고, 진행 Match/네트워크 descriptor/기존 Hub root의 중복 방지 조건은 유지한다. GameFlow를 새로 만들거나 authored Scene·카메라를 바꾸지 않는다. 직접 Hub 실행과 Startup의 정식 Hub 진입을 실제 Play에서 각각 확인했으며, 진행 Match의 Additive 방문은 새로운 Hub actor를 만들지 않는 검사도 통과했다. [메뉴 귀환 경계](../02_architecture/03_scene-flow/screen-management-api.md)를 따른다.

GameFlow 없는 독립 Hub에서의 새 미션 재출격 제한은 기존 그대로다. 이 수정이 전체 독립 실행 게임 흐름을 새로 제공하는 것은 아니다. 초기 양성 검사 2개는 Edit Mode의 `Awake` 부재로 실패했으며 제품 카메라 코드에 우회 가드를 추가하지 않고 실제 Play fixture로 교정했다. 해당 실패 기록과 최종 통과 기록을 로컬 검수 폴더에 함께 보존한다.
