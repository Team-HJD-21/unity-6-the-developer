# 2026-11-13 무기·탄창 패널 리뷰

사용자 요청에 따라 Player 옆에 나타나던 탄약·재장전을 하단 현재 무기 UI 오른쪽으로 옮겼다. 구현·검증 기록이며 최종 미감은 사용자 화면 리뷰 대상이다. 공통 기준은 [공통 UI 규칙](common-ui-rules.md), 표시와 입력 경계는 [Player UI API](../02_architecture/06_player/player-ui-api.md)를 따른다.

## 후속 숫자 전용 탄약 표시

사용자 확인으로 탄약은 현재/최대 숫자만 유지한다. 실탄 띠와 소비 후 소멸 이미지를 제거하고 수량을 기존 탄약 영역 중앙에 배치했다. 실제 발사 성공의 숫자 확대·밝기 변화·작은 반동과 재장전 회전 표시는 유지한다. 재장전 중 수량과 작은 화살표를 위아래로 분리하며, 스패너는 기존 무한 표식을 사용한다. 무기 번호의 외부 왼쪽 배치는 유지한다. 아래 실탄 이미지 관련 내용은 변경 이전의 검증 기록이며, 최신 구현은 이 항목과 공통 UI 규칙을 따른다. 후속 실제 검수 자료는 로컬 `NumericAmmoReview20261113`에 보관한다.

숫자 전용 변경 뒤 기존 제작/프리팹 검사 2/2가 통과했다. 실제 Initial_Stage의 정상 필드 진입 후 발사 API 3회에서 15→14→13→12, 재장전 API 완료 후 15를 확인했다. 정상 시간의 실제 렌더 141프레임에서 숫자 배율 최대 약 1.098→1, 발사 반응 약 0.982→0, 재장전 회전 44프레임을 관측했다. Sniper 5발과 Spanner 무한 표시도 확인했다. 75%·110% 실제 화면을 보관한다. 110% 검수에서 CLI 검수 포인터는 정상 프레임에 (0, 0)으로 읽혀 반원을 열지 못했으므로, 이번에는 열린 반원 입력 검수를 통과한 것으로 표시하지 않는다. 제품 입력/포커스 설정을 바꾸지 않았으며 OS 입력·Standalone 빌드는 이번 후속에서 실행하지 않았다.

## 후속 번호 정렬

사용자 추가 요청으로 번호를 **패널 바깥 왼쪽**으로 옮겼다. 패널은 450×100 reference, (50, 64)이며 번호 열은 28×88, (10, 70)이다. 4개 번호를 22 간격으로 세로 중심에 맞추고 번호 뒤에 별도 바탕을 넣지 않는다. 일반 번호의 밝기를 올리고 1 reference px 글자 그림자로 배경 위 가독성을 보완했다. 총 그림과 탄창의 화면 위치·크기는 유지하며 패널 내부의 옛 번호 여백만 제거했다. 무기명도 바뀐 총 영역에 맞춰 정렬했다.

아래 탄창 통합 1차 기록의 내부 번호 배치는 이 후속 정렬로 대체한다. 1차 모션은 탄약 동작 검증 자료로 보존하고, 최신 번호 위치의 실제 화면과 결과는 로컬 `WeaponNumberReview20261113`에 따로 기록한다.

최종 정렬은 실제 1920×1080 Game View에서 확인했다. HUD 75%의 번호 열과 패널 사이 간격은 9px, 세로 중심 차이는 0px이며 번호 4개의 raycast가 모두 해당 버튼에 도달했다. 정상 프레임 InputSystem/EventSystem으로 외부 4번 번호 클릭 시 Sniper 5발로 교체됐고, 뒤이은 탄창 클릭에서는 5발을 유지하며 발사 이벤트가 없었다. HUD 110%에서 스킬 반원을 연 상태에도 번호는 패널 밖에 있고 패널과 반원 사이 14px 간격을 유지했다. 정렬 변경 뒤 관련 Editor 검사 2개를 다시 실행해 2/2 통과했다. 이번 후속 검수는 OS 마우스 입력·Standalone 빌드 인수와 구분한다.

## 탄창 통합 1차 반영

- 기존 얇은 무기 프레임을 488×100 reference 크기의 패널로 넓혔다. 왼쪽 번호 레일·총 그림·오른쪽 탄창 순서다. 총 그림은 기존 원본을 234×72 안에서 비율을 유지해 표시한다. 다른 후보 무기 그림을 겹치지 않으며 한 장의 교체 회전과 기존 이름 호버/잠깐 표시를 유지한다.
- 탄창은 현재/최대 수량과 실제 탄환 띠다. 15발과 5발 탄창을 실제 capacity대로 표시하며 스패너는 무한 표식이다. 최대 32개의 제작된 탄환을 재사용하고, 실행 중 UI 오브젝트를 새로 만들지 않는다.
- 실제 `PlayerAttack.ShotFired` 성공에만 소비한 탄환의 짧은 밝기·위로 소멸, 수량 1.1→1 확대·복귀, 작은 반동을 적용한다. 기본 반응은 0.2초이며 `ShotFeedbackSeconds`로 편집한다. 무기 교체로 15→5가 되거나 처음 연결·저장 복원되는 것은 발사 효과가 아니다.
- 재장전은 오른쪽 탄창 자리의 얇은 회전 화살표다. 원본 `PlayerWeaponAmmo.ReloadProgress`를 읽고 완료하면 실제 탄창으로 돌아온다. 별도 임의 시간이나 장식용 진행률·설명 문장은 추가하지 않았다.
- `AmmoRoot`는 공유 무기 패널의 자식이다. Player 월드 좌표·조준 방향을 따라가지 않으며 무기 부모의 HUD 크기·접힘·첫 등장 스캔을 상속한다. 중복 배율 항목은 제거했다. XP 팝업은 계속 Player 주변 World Space 표시다.
- 패널 전체 배경을 UI raycast 영역으로 처리한다. 필드 커서도 같은 패널 경계를 따르며, 탄창 위 클릭이 필드 사격으로 전달되지 않는다. 내부 번호 레일은 현재 총의 투명 클릭 면보다 위에 그려 버튼이 가려지지 않는다.

새 외부 디자인 에셋이나 라이브러리는 추가하지 않았다. 기존 Nine-slice 프레임·실탄 그림·폰트·UGUI 재장전 벡터를 재사용해 다른 HUD와 맞췄다. 일반 편집은 `PlayerSkillHUD.prefab` 안에서 한다. `HudAmmoDockSetup.Configure`는 이 영역만 적용하며, 전체 제작 경로도 기존 탄창/탄환 객체를 재사용한다. 제작 도구를 재실행하면 제작 기본값이 적용되므로 수동 편집 뒤 무작정 실행하지 않는다.

## 실제 화면 검수

1920×1080 Game View, 정상 게임 시간으로 확인했다. 생성 시안이 아닌 실제 렌더 PNG와 프레임별 JSON을 보관한다.

| 항목 | 관측 |
| --- | --- |
| 발사 | 실제 `TryFire` 3회가 모두 성공, 15→14→13→12. 밝기/소멸 반응 최대 0.99 이상과 수량 약 1.10 배율 후 정상 복귀. |
| 재장전 | 실제 `TryReload` 성공. 화살표 회전을 거쳐 12→15로 복귀하고 발사 반응은 0으로 정리됨. |
| 교체 | Sniper→Spanner→CryoBlaster→DefaultGun 모두 성공. 해당 탄창/무한 표시와 한 장 회전 유지. 교체 녹화의 발사 반응은 전 구간 0. |
| 실제 UI 입력 경로 | 정상 프레임 InputSystem/EventSystem으로 4번 버튼을 눌러 Sniper 5발 선택을 확인한 다음 탄창을 클릭했다. 탄약은 5발 유지, 발사 이벤트 0. 입력 자체가 무시돼 나온 음성 결과와 구분하도록 먼저 번호 클릭의 성공을 확인했다. |
| 75% | 패널 우측 375px, 반원 사각형 좌측 690px. 간격 315px이며 탄창은 패널 안에 있음. |
| 110% | 반원을 실제로 연 상태에서 패널 우측 550px, 반원 사각형 좌측 564px. 간격 14px이며 탄창은 패널 안에 있음. |

초기 확장안에서는 110%에서 패널 오른쪽과 반원이 겹치는 것을 실제 화면에서 발견했다. 패널을 화면 왼쪽으로 붙이고 번호를 안쪽 왼편으로 정리해 수정했다. 총 그림 크기는 줄이지 않았다. 최종 자료에는 수정 후 화면을 사용한다.

사격·재장전은 실제 게임 API, 번호/탄창 클릭은 정상 프레임 InputSystem 입력이다. 이 작업에서 OS 키보드·마우스로 재검수한 것으로 표시하지 않는다. Standalone 빌드·원격 Client는 실행하지 않았다. 검수 입력 장치와 임시 입력 차단은 제거/복구한다.

## 자동·에셋 검사

`CombatHudPresentationTests`의 발사·탄약·무기 교체·고정 위치·최대 배율·번호 raycast·기존 호버/드래그 검사 2개와 `PlayerWeaponHudTests` 2개가 통과했다. 공유 툴팁 알파만으로 먼저 종료하던 호버 검사는 해당 스킬 그림의 집기 애니메이션까지 기다리도록 보강했으며, 실패 기록도 보존했다.

제작 반복 검사 1개도 통과해 합계 **5/5 통과**다. 기존 탄창/탄환 identity, 한 개의 탄창, 32개 소멸 이미지, 재장전/수량/번호/무기명 그래픽의 복구를 확인했다. 이 검사에서는 프리팹을 저장하지 않는다.

최종 사격/재장전 142프레임, 교체 111프레임, UI 클릭 109프레임을 기록했다. 탄창 offset은 전 구간 (388, 50)으로 고정됐고, 발사 반응은 약 0.995/수량 약 1.099까지 나타난 뒤 0/1로 복귀했다. 교체와 UI 클릭 영상의 발사 반응은 전 구간 0이었다.

원본 결과는 로컬 `Docs/Local/Validation/HudV6/AmmoDockReview20261113`, PNG/JSON 모션은 `manual/motion/ammo-dock-*`에 있다. 공유용 로컬 뷰어 `hud-ammo-dock-20261113`은 원본 화면·사격·교체·클릭 재생과 무기 영역 확대를 제공한다. 이미지 픽셀은 수정하지 않는다. 뷰어는 PNG 참조와 JavaScript 구문을 검사하며, 내장 브라우저의 `file:` 자동 열기 제한 때문에 브라우저 재생 동작 인수와 구분한다.
