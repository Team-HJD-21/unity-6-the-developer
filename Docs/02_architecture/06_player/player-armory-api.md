# 플레이어 무기고

2026-11-14 사용자 요청 기준. 무기 레벨·토큰은 현재 PlayerExperience와 같은 actor 수명의 런타임 데이터다. 백엔드·계정·PlayerPrefs·디스크 저장이나 별도 영구 성장 규칙을 추가하지 않는다.

## 진입·입력

첫 출격 전 우주선처럼 `EventSystem.current`가 없는 경우에만 Station이 UI 입력 모듈을 생성한다. 닫을 때 자신이 만든 모듈만 제거하며, 필드 등에서 제공하는 기존 EventSystem은 재사용하고 유지한다.

- `SpaceShipGrayBox.unity`의 기존 `WeaponChoice`에 `PlayerArmoryStation`을 연결한다. 오브젝트의 그림·위치·기존 GUID를 유지한다.
- 시작 허브와 진행 중 우주선 방문 모두 `PlayerControlState.IsInSpaceship`인 로컬 생존 actor만 상호작용한다. 기존 `ILocalInputConsumer` 주입을 받은 `PlayerArmory`를 조회하고 거리(기본 3)를 검사한다.
- 가까이 가면 `[F] 무기고`가 표시된다. F로 열고, F·Esc·닫기 버튼·거리 이탈·사망·전환·비활성화 시 닫는다. 입력 잠금은 자기 lease만 해제한다.
- `PlayerArmory.prefab`은 편집 가능한 Canvas/UI다. 문구는 한글로 표시하고 프로젝트의 한글 지원 폰트를 연결한다. 기존 무기 그림과 UI 계층·텍스트·버튼·아이콘의 Inspector 참조를 유지하며 실행 중 UI 트리를 코드로 만들지 않는다.
- 무기고가 열린 동안 로컬 이동·전투 입력을 막는다. 필드 시간이나 다른 메뉴의 잠금 상태를 직접 변경하지 않는다.

## 장착

2026-11-15 한글 표시: 무기고는 `PlayerArmoryThinMulmaru SDF.asset`을 사용한다. 기존 얇은물마루(ThinMulmaru) 원본에서 무기고에 필요한 글자를 미리 구운 Static 폰트로, 실행 중 글자 추가로 atlas가 변경되지 않는다. 제목·버튼·상호작용 안내·장착 상태·강화 전후 비교와 안내 문구를 한글로 표시한다.

- 스패너는 고정이며 기본총·냉각총·스나이퍼 중 서로 다른 두 총을 장착한다. 기본 구성은 기본총·냉각총이다.
- UI의 총기 선택은 비교 대상만 바꾼다. `총기 1/2에 장착`을 눌러야 실제 장착 목록이 바뀐다. 다른 슬롯의 총을 선택하면 두 총을 교환한다.
- `PlayerWeaponSelection.IsWeaponAuthored`는 프리팹 제작 여부, `IsWeaponAvailable`은 제작 여부와 현재 장착 여부를 확인한다. Tab·휠·숫자키·HUD·상태창은 모두 장착 목록을 따른다. 기존 숫자키 매핑(1 스패너, 2 기본총, 3 냉각총, 4 스나이퍼)은 유지한다.
- 시작 허브와 첫 출격은 별도 actor를 사용하므로 로컬 입력 scope별로 두 장착 종류만 한 번 전달한다. 이 준비 캐시는 SubsystemRegistration에서 비우며 경험치·토큰·무기 레벨을 전역 저장하지 않는다. 같은 판의 우주선 왕복은 기존 actor 상태를 유지한다.

## 임시 강화 수치

`Assets/Data/Player/PlayerArmorySettings.asset`에서 조절한다. 기본 레벨 1, 최대 3이다. 비용은 무기 종류에 관계없이 단계당 토큰 1개이며 스패너 강화는 제공하지 않는다.

| 항목 | Lv 1 | Lv 2 | Lv 3 |
| --- | --- | --- | --- |
| 무기 피해 배율 | 1 | 1.15 | 1.30 |
| 기본총 발사당 탄환 | 1 | 3 | 5 |
| 스나이퍼 최대 적중 적 수 | 2 | 3 | 4 |
| 냉각 감속률 예약값 | 20% | 35% | 50% |

공격 간격·사거리·탄창·재장전 시간은 강화로 변경하지 않는다. 기본총 산탄 여러 발도 탄창에서는 한 발을 사용한다. 무기 피해 배율 뒤 기존 공통 공격력 배율·치명타 계산을 적용한다.

냉각은 기존 방침대로 **실제 피해만 적용**한다. Enemy 쪽에 사용할 감속 구현이 아직 없어 감속 값은 `둔화율 (예정)`으로 비교하며 미연결 상태를 UI에 명시한다. Enemy 내부 이동이나 구형 Monster API를 수정하지 않는다.

## 보상과 비교

- `PlayerExperience.LevelChanged` → `PlayerArmoryState.GrantLevelRewards` → 무기고 토큰 표시. 레벨당 기본 1개이며 여러 레벨 상승분을 모두 지급한다. 이미 보상받은 레벨은 다시 지급하지 않는다. 기존 스탯 포인트와 별도 잔액이다.
- `PlayerAttack.TryGetWeaponStats(weapon, level)`로 현재/다음 단계의 피해·공격 간격·탄환 수·사거리를 조회한다. 실제 사격도 같은 `GetShotSettings`를 사용한다. UI 비교를 위해 현재 무기를 변경하거나 토큰을 미리 소비하지 않는다.
- 토큰 부족·최대 레벨·무기고 밖 요청은 거부한다. NGO Client의 임의 강화 쓰기는 거부한다. 원격 강화 명령/RPC와 Client 동기화는 이번 범위가 아니다.

## 체크포인트

- 새 `/armory` section v1은 장착 두 총·레벨별 보상 진행·토큰·세 무기 레벨을 보관한다. 총 보상과 소비량을 대조하고 중복 장착·잘못된 레벨·제작되지 않은 총을 복원 전에 거부한다.
- 복원 순서 210에서 장착 목록을 먼저 적용하고 `/weapon`(220)을 복원한다. Apply/Rollback 모두 상태를 되돌리고 UI를 닫는다.
- `/weapon` v4는 탄환별 적중 한도와 관통 이력을 함께 보존한다. v1~v3 탄환은 기존 무제한 한도 0으로 읽는다. 새 `/armory` section이 없는 과거 전체 저장의 자동 마이그레이션은 제공하지 않는다.

## 검증

`PlayerArmoryTests`, `PlayerArmoryRuntimeTests`, `PlayerBulletRuntimeTests`가 진입점이다. 독립 fixture의 실제 프레임 입력/UI/사격 검사와 실제 우주선·출격 왕복·Host/Client 인수는 구분한다. 결과는 실행 후 기록한다.

2026-11-15 한글화 검증: 무기고 관련 테스트 12/12 통과. 독립 실행 환경의 Canvas 캡처에서 얇은물마루 한글 문구와 강화 비교가 겹침 없이 표시됨을 확인했다. 실제 우주선 Scene에서의 수동 F 조작과 원격 Client 검증은 별도다.

2026-11-15 첫 출격 전 입력 수정: 무기고 테스트 13/13 통과. EventSystem이 없는 fixture에서 키 입력 처리와 실제 포인터 입력 모듈·레이캐스트·버튼 콜백을 검사했다. 실제 Startup → SpaceShipGrayBox 경로도 자동 실행해 필드 미진입 상태의 EventSystem 부재, 무기고 열기, 스나이퍼 장착 버튼 클릭, 닫기를 확인했다. 사람이 직접 조작한 인수와 원격 Client 검증은 별도다.
