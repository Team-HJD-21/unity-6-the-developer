# 플레이어 스킬 트리와 하단 후보

2026-11-15 사용자 요청 기준. `I → 스킬 트리`에서 해금과 하단 후보 네 칸을 편집한다. 실제 사용 슬롯은 기존 Q/E 두 칸이며, 하단 원형 선택창에서 후보를 Q/E로 드래그하는 방식은 유지한다.

## 트리와 임시 재화

- 시작 노드는 시한폭탄이며 무료로 해금되고 후보 1에 배치된다. 나머지 후보는 비어 있고 Q/E는 직접 선택한다.
- 폭탄 아래에서 공격 업그레이드 / 설치형으로 갈라진다. 공격형 첫 노드는 양손 무기, 설치형은 터렛 → 방벽 → 유도 비콘 → 포털 순이다. 이 배치는 임시다.
- 포털은 플레이어 프리팹·설치 미리보기·이동 입력까지 연결한다. 전용 세로형 A/B 이미지와 좌우 발판 콜라이더를 사용하며 자세한 외형·충돌·입력은 [포털 API](player-portal-api.md)를 따른다.
- `PlayerSkillResearch`가 `PlayerExperience.LevelChanged`에 따라 오른 레벨당 스킬 토큰 1개를 지급한다. 이미 보상한 레벨은 중복 지급하지 않는다. 무기고 강화 토큰·스탯 포인트와 별도 잔액이다.
- 폭탄을 제외한 노드는 선행 노드 해금 후 토큰 1개로 해금한다. 선택한 노드를 해금한 다음 원하는 후보 버튼을 눌러 배치한다. 이미 다른 후보에 있는 스킬은 두 후보 위치를 교환한다.
- 같은 화면에서 해금된 각 스킬을 최대 3레벨까지 강화한다. 강화당 같은 스킬 토큰 1개를 소비하며 각 단계는 원본 대비 +15%다. 폭탄·터렛·양손 무기는 피해량, 방벽은 최대 연결 거리, 비콘은 유인 반경, 포털은 설치 반경을 늘린다. UI의 현재/다음 값은 실제 스킬 값에서 조회한다. 이미 배치된 비콘의 반경은 배치 당시 값을 유지하며 다음 설치에 강화가 적용된다. 이미 설치된 폭탄·터렛의 다음 피해는 소유자의 현재 강화 배율을 따른다.
- 후보에서 빠진 스킬이 Q/E에 있으면 해당 사용 슬롯만 비운다. 설치 프리뷰는 취소하며 이미 설치된 본체를 없애거나 쿨다운을 초기화하지 않는다.
- 상태는 현재 PlayerExperience actor와 같은 수명이다. 백엔드·계정·디스크·PlayerPrefs 영구 저장을 추가하지 않는다. 시작 허브와 첫 출격의 actor가 다르면 XP와 동일하게 새 상태다.

## 호출과 표시

- `PlayerStatusPanel`의 로컬 소유자 → `PlayerSkillTreePanel` → `PlayerSkillResearch.TryUnlock/TrySetCandidate`가 변경 진입점이다. 원본에서 재화·선행 조건·실제 스킬 설정·조작 및 Host 쓰기 권한을 검사한다.
- `PlayerSkillController.Candidate`가 원형 선택창과 구형 카드 선택창에 같은 후보 목록을 전달한다. `TrySelect/TryEquip/TryUse`는 해금과 후보 포함 여부를 검사한다.
- 원형 섹터의 위치·바늘·툴팁 위치는 스킬 ID 고정 순서 대신 실제 후보 위치를 따른다. 바뀐 후보도 같은 드래그·Q/E 장착 API를 사용한다.
- 원형 후보와 구형 카드의 이름도 동일한 `PlayerSkillDescriptions.Name`에서 갱신한다. 새 한글 이름을 구운 Static 폰트를 사용해 고정 이름 잔존과 글자 누락을 방지한다.
- 트리의 버튼·선·카드·텍스트는 `InitialStagePlayerHUD.prefab`에 제작한다. 전용 Static 얇은물마루 폰트를 사용하며 실행 중 트리 UI나 폰트 atlas를 생성하지 않는다.
- 스킬 화면을 열 때만 상태창 높이를 780에서 960으로 늘리고 스크롤 영역 높이를 520으로 사용한다. 스테이터스로 돌아오면 기존 창 크기를 복원한다. 트리·선택/강화 정보·후보 배치 영역은 각각 나눈다.
- 선택한 카드는 금색, 해금한 카드는 청록색, 잠긴 카드는 어두운 색과 상태 문구로 구분한다. 후보 네 칸은 번호·아이콘·이름·배치 상태를 각각 표시한다. 선택한 스킬이 이미 들어간 칸에는 `배치됨`, 다른 칸에는 `클릭하여 교체` 또는 `클릭하여 배치`를 표시한다. 잠긴 스킬 선택 중에는 후보 변경을 막고 해금한 스킬 선택을 안내한다.

## 양손 무기

- `PlayerDualWieldSkill`은 Q/E로 사용한다. 기본총·냉각총·스나이퍼에서 8초 유지하고 사용 시점부터 20초 재사용 대기한다. 스패너로는 활성화하지 않는다.
- `PlayerWeaponVisual`의 두 SpriteRenderer는 조준 방향과 무관하게 몸체 좌우 같은 높이의 손 위치에 배치한다. 각 손·총구는 같은 마우스 커서를 향한다. 각 총구의 실제 위치에서 발사하며 무기 변경 시 현재 총의 외형·탄환·특성을 따른다.
- `PlayerAttack`은 기본총의 산탄·스나이퍼 관통 설정을 두 총구에 동일하게 적용한다. 냉각총은 원점·가림·표시 상태가 독립적인 두 `PlayerCryoSpray`를 사용한다. 감속은 기존과 같이 미적용이다.
- 같은 발사 간격에 양손이 함께 공격하지만 탄약 소비는 기존 한 번이다. 빈 탄창·재장전·설치·수리·메뉴·사망과 필드 정지 제한을 유지한다. 스패너/수리/우주선에서는 두 번째 총을 숨기며 사망·비활성화 시 효과를 종료한다.
- 시간은 `FieldSimulationTime`을 따른다. 두 냉기 표시는 별도 주입 난수 스트림을 사용한다. 사운드는 추가하지 않는다.

## 체크포인트와 제한

- `/loadout` v3는 Q/E와 해금 비트·보상받은 레벨·잔액·후보 네 칸·개별 강화 단계를 한 번에 보관한다. 선행 조건·해금 및 강화 비용 회계·중복/잠긴 후보·후보 밖 Q/E를 복원 전에 거부한다. Apply와 Rollback 모두 함께 복원한다.
- 양손 스킬은 기존 스킬 writer 계약의 `/skill/6` v1로 남은 유지·대기 시간을 저장한다. 과거 `/loadout` v1/v2에서 새 연구 상태로의 자동 마이그레이션은 이번 범위에 포함하지 않는다.
- 원격 Client의 임의 해금/후보 쓰기와 양손 활성화는 거부한다. 원격 요청 RPC·성장 복제는 이번 범위가 아니다.

검증 진입점은 `PlayerSkillTreeRuntimeTests`, `PlayerSkillSelectionTests`, `PlayerStatusPanelTests`, `CombatHudPresentationTests`, `PlayerCryoSprayTests`다. 독립 fixture 검사와 실제 Scene·사람의 조작·Host/Client 인수는 별도로 기록한다.

2026-11-15 검증: 스킬 트리 통합 fixture 12/12 (F 회수·세로형 포털 후속 포함), 자유 조준·수리 55/55, I 상태창 9/9, 하단 전투 HUD 표현 4/4, 냉각 분사 15/15 통과. 마지막 조준 보완 뒤 좌우·수직·대각선 손 위치 검사도 재통과했다. 포털 제작 프리팹의 실제 설치·R 이동·F 회수와 수리/재장전 입력 분리, 좌우 손 위치와 세 총기 실제 발사·동일 탄약 소비, 강화 비용·실제 수치·저장/롤백, 후보 교체 시 이름 갱신을 검사했다. `.meta` 검사는 오류 0개다.

트리의 위/아래를 Unity UI 카메라로 별도 렌더해 글자 넘침이 없음을 확인했다. 첫 화면에서 폭탄과 두 갈래의 첫 스킬이 잘리지 않도록 카드 높이와 간격을 조정하고, 분류 제목 아래에 배경을 두어 연결선이 글자를 가리지 않게 했다. 스크롤바의 내부 영역도 창 높이를 따르도록 정리했다. 이 렌더는 실제 Field Scene에서 사람이 조작한 인수와 다르며 Host/Client 전송·빌드는 실행하지 않았다.

## 포털 조작

해금·후보 배치·Q/E 등록 후 두 지점에 설치한다. 근처에서 R을 한 번 누르면 반대편으로 이동하며 F는 가까운 자기 포털·터렛 중 하나를 회수한다. 빈 슬롯에 재설치할 수 있고 한 쌍만 유지한다. 동일 R 누름은 놓을 때까지 수리·재장전에 재사용하지 않는다. 포털이 없는 곳의 기존 R 수리·재장전과 F 터렛 회수는 유지한다. 화면에 R/F 안내를 표시하며 지면·벽·도착 공간·필드 시간·권한 검사는 기존 포털 원본 API를 따른다.

포털 외형은 전용 세로형 A/B 이미지로 교체했으며 프리뷰·트리·HUD 아이콘에 연결했다. 회수 안내는 실제 F 대상과 일치하며, 가까운 자기 터렛·포털 중 하나만 회수한다. 세부 프리팹과 검증은 [포털 API](player-portal-api.md)를 참고한다.

2026-11-15 세로 확장/배치 슬롯 후속: `PlayerSkillTreeRuntimeTests` 12/12, `PlayerPortalSkillTests` 7/7, `PlayerStatusPanelTests` 9/9 통과. 후보의 이름·아이콘·배치 상태와 실제 원형 선택창 반영, 스킬 창 확대/복귀, 포털 받침 충돌과 중앙 통과를 검사했다. 1920×1080 독립 Unity UI 렌더의 위/아래 화면, 텍스트 넘침 없음, 전용 Static 폰트의 319개 요청 글리프를 확인했다. 컴파일·`.meta` 오류 0개. 실제 Scene 수동 조작·멀티플레이·빌드 검증은 별도다.

## 설치 표시 연출

설치 성공 후 본체 초기화·Scene/Match 시간 연결을 마친 호출부가 `PlayerPlacementPresentation.Play()`를 호출한다. 터렛은 0.34초 착지/포신 전개, 방벽은 0.36초 본체 전개와 에너지 표시, 비콘은 0.32초 전개, 폭탄은 0.24초 착지/작은 반동, 포털은 0.44초 세로 상승이다. 기존 그림을 프리팹의 표시 전용 SpriteRenderer로 잠시 그린다. 원본 Transform·총구·충돌 위치·설치 판정·효과 시작 시점은 바꾸지 않는다.

표시 복사본은 각 원본 아래에 제작하고 같은 Sprite/Material/정렬/피격색을 따른다. 방벽/비콘의 에너지 선은 선 두께로 전개한다. 완료·비활성화 때 원래 표시를 복구하고 재활성화·체크포인트 복원에는 설치를 다시 재생하지 않는다. 필드 정지를 따르며 사운드와 새 입력 잠금은 추가하지 않았다. 폭탄 타이머는 움직이는 표시를 따라가고 폭발 기능/효과는 그대로다.

`PlayerPlacementPresentationTests` 6/6 통과: 제작 프리팹 5종의 표시 이동 중 원본·콜라이더 bounds 보존, 비활성화/재활성화, 완료 시 복구, 필드 정지/재개를 확인했다. Unity 카메라 연속 30프레임으로 각 연출을 별도 렌더했다. 실제 Field Scene 사람의 조작 인수는 별도다.
