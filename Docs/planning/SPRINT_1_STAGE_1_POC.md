상태: 실행 기준

[문서 목차](../README.md)

> Sprint Goal: 최소 Graybox에서 터렛 거점을 확보하고 제한 전력을 배분해 전선을 밀고 당기며, Player가 약한 전선을 지원하는 한 사이클을 같은 Build에서 검증한다.

## 1. 검증할 핵심 가설

1. 직접 전투보다 터렛 중심 전선 운영이 게임의 고유한 재미로 작동한다.
2. Player가 주 화력이 아니어도 수리·보조 공격·군중 제어로 충분히 개입한다고 느낀다.
3. 모든 터렛을 켤 수 없는 전력 한도가 실제 전략 선택을 만든다.
4. 거점 확보와 상실이 전장 확장, 전선 전진·후퇴로 명확하게 보인다.
5. Enemy가 Player만 추격하지 않고 약한 터렛 거점과 핵심 시설을 합리적으로 공격한다.

## 2. 최소 플레이 흐름

```text
Spaceship에서 준비
→ Planet 출격
→ 초기 Enemy 제거와 첫 터렛 거점 확보
→ 전력 한도 안에서 터렛 활성화·강화
→ 약한 전선으로 이동해 지원
→ 새 거점 확보 또는 기존 거점 상실
→ 전장 확장 또는 전선 후퇴
→ 임시 승리·실패 조건으로 종료
→ 결과 확인과 Spaceship 복귀
```

## 3. 완료 기준

- [ ] 최소 Graybox Map에서 Player가 출격할 수 있다.
- [ ] 첫 터렛 거점을 확보하고 터렛을 활성화할 수 있다.
- [ ] 전력 한도 때문에 모든 터렛을 동시에 켤 수 없다.
- [ ] 거점 확보에 따라 전장 또는 다음 목표가 확장된다.
- [ ] 거점 상실 시 전선이 후퇴하는 상태를 확인할 수 있다.
- [ ] Enemy가 목표를 선택하고 터렛 또는 핵심 시설을 공격한다.
- [ ] Player가 약한 전선으로 이동해 전투에 개입할 수 있다.
- [ ] 한 사이클 안에서 전선의 전진 또는 후퇴가 보인다.
- [ ] 임시 승리·실패 조건으로 한 판을 끝낼 수 있다.
- [ ] 2026-10-02에 전체 팀이 같은 Build로 통합 플레이 테스트를 수행한다.

## 5. 통합 순서

```text
D · 터렛 상태·평가 데이터
        ↓
E · 목표 선택 AI와 공격 결과
        ↓
C · 거점 확보·상실과 전선 확장
        ↓
A · Player 지원·임시 승패·통합 Build
        ↓
전체 팀 · 2026-10-02 Playtest
```

B의 Network-aware 조사는 위 통합을 막지 않는 병렬 작업이다. 실제 실시간 협동 구현은 이번 범위에 포함하지 않는다.

- 완성도 높은 Tilemap, 최종 Art와 UI polish
- 모든 Planet, Enemy, Turret 제작
- 실시간 협동 멀티플레이 완성
- 최종 경제 Balance와 장기 성장 확정
- Spaceship 꾸미기, Pet, Mini-game
- 정확한 낮/밤 길이와 최종 환경 효과

2026-09-26 회의에서는 동적 전선과 지역 해금을 우선 검토하고 기존 스테이지 방식을 뒤로 두었다. 두 우선 후보 가운데 최종안을 정하거나 병행 구현 범위·일정을 확정하지는 않았다. 회의에서 새 마감이나 Sprint 담당 재배정도 없었다. 세 후보의 설명과 이번 회의 정리는 [9월 22일 비교 문서](../2026-09-22-progression-options.md)와 [9월 26일 계획 메모](2026-09-26-stage1-planning.md)를 참고한다.

Stage 1에서는 정식 패배 화면 대신 디버그 부활 버튼 또는 무적 상태로 플레이어 사망을 처리한다. Region 단위 적 목표 선택은 조수빈이 우선 시험한다. 이는 임시 PoC 동작이며 최종 승패·체크포인트·전선 규칙 확정이 아니다.

2026-09-26 회의에서는 동적 전선과 지역 해금을 우선 검토하고 기존 스테이지 방식을 뒤로 두었다. 두 우선 후보 가운데 최종안을 정하거나 병행 구현 범위·일정을 확정하지는 않았다. 회의에서 새 마감이나 Sprint 담당 재배정도 없었다. 세 후보의 설명과 이번 회의 정리는 [9월 22일 비교 문서](../2026-09-22-progression-options.md)와 [9월 26일 계획 메모](2026-09-26-stage1-planning.md)를 참고한다.

- 최종 승리 조건: 마지막 거점, Boss, 별도 목표 중 선택

## 8. Issue와 PR 규칙

- 모든 업무를 GitHub Issue로 만들고 담당자, 영역, 우선순위와 완료 조건을 기록한다.
- PR에 관련 Issue와 테스트 결과를 남긴다.
- 다른 사람의 Scene을 직접 수정하지 않는다.
- 같은 Scene에 필요한 기능은 가능한 한 Prefab 또는 분리된 Adapter로 전달한다.
- 막힌 내용은 오래 추측하지 않고 팀에 공유한다.
