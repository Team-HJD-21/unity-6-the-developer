# 2026-10-30 기획 보강회의 검토 기록

기준일: 2026-10-31
상태: 전체 개인별 자동 전사·수기 대조 / 합의 방향·후보·실행 보고 분리

참석: 황재동·양현석·조수빈·김진태·이영빈. 사용자가 전원 참석을 확인했다. 근거는 공유 드라이브 `The-Developer-V2/회의록/2026-10-30_기획_보강회의`의 정리 회의록, `2026-10-30_화자별전사.md`, 보조 수기 `20261030_기획.md`다. 이전의 수기만으로 작성한 검토 기록을 완성된 전사 대조로 보강했다. 직접 청취 검수·코드 실행 검증은 하지 않았다.

10월 31일 추가 확인은 [다음 날 정기회의 기록](2026-10-31-regular-meeting.md)을 따른다. 특히 우주선 입장 시 필드 정지는 다음 날 재확인한 범위를 함께 읽는다. 원본 회의록·녹음과 작업 중인 코드·Scene은 이 Docs 변경에 포함하지 않는다.

## 1. 자동 활성화의 합의된 흐름

[00:00:04–00:05:17]

- 사거리 안 적 수가 많은 터렛을 먼저 켜고, 동률이면 화력을 비교한다. 황재동은 화력을 **전력 1당 공격력**으로 설명했다. 전력 10·공격력 100 → 비교값 10은 예시이며 DPS나 코드 산식을 검증한 것이 아니다.
- 자동 활성화를 시작하면 켜진 터렛을 **일시에 OFF**한 뒤 우선순위대로 순차 ON한다. 편의 기능의 대가로 화력 공백이 생기는 방향을 유지한다.
- OFF 직후 전력이 즉시 전량 충전되지는 않는다. 기존 점진 전력 반환·냉각 시간을 고려한다. 남은 과열이 다 식은 뒤에야 OFF/반환을 시작하는 과거 방향으로 되돌리지 않는다.
- 차례가 된 터렛의 전력이 부족하면 해당 터렛을 예약하고 필요한 양까지 회복될 때까지 기다린다. 단순히 뒤 순위로 건너뛰는 방식 대신 켜짐을 보장한다.
- 잠금·파괴·대상 변경·취소·재계산 같은 예외 계약은 이 대화만으로 확정하지 않는다. 공유 전력 초과 가능성을 질문했고 황재동은 순차 ON과 본인 테스트 결과를 설명했다. 이 문서는 동시성·실제 구현의 성공 증거가 아니다.

## 2. 성장·승급·CU의 경계

[00:11:47–00:26:58]

- 터렛의 **현장 승급**과 **전역 세부 능력치 성장**을 분리한다. 고효율/고화력 두 갈래 대신 스킬트리 형태로 구체화하는 방향이다.
- 플레이어와 터렛의 UI·성장 방식은 일관되게 하되 하나의 능력치 트리로 합치지 않는다. 한 화면에서 전환해 보는 구상이다.
- CU 업그레이드를 터렛 성장의 관문으로 둔다. 재화와 특정 스테이지/보스 클리어 조건을 함께 요구하고 CU 성장에 따라 터렛 승급 상한을 여는 방향이다. 클리어 번호·가격·레벨 수·트리 도식은 미정이다.
- 터렛 능력치 후보는 공격력, 과열까지의 허용량, 냉각 시간, 포신 회전 속도, 명중률, RPS(초당 발사 수), 체력이다. 명중률은 탄의 흔들림/분산 보정 설명이며 임의의 명중 확률 공식이 아니다.
- 개별 터렛 전력 소모는 등급별 고정 비용으로 두고 직접 강화 항목에서 제외하는 방향이다. CU의 전력 효율은 필드 터렛 소모에 공통으로 영향을 준다.
- CU 총 전력량과 전력 효율은 같은 단계에 동시에 올리기보다 교차 강화한다. 체력도 CU 속성으로 논의했다. 정확한 단계·감소율은 미정이다.
- 황재동이 터렛 스킬트리 안을 만들어 공유하기로 했다. 내일까지는 어렵다고 말했으므로 10월 31일을 확정 납기로 추가하지 않는다. [00:43:36–00:43:52]

## 3. 필드·CU·우주선 행동과 귀속

[00:27:39–00:48:15]

| 행동 | 기본 방향 | 남은 설계 |
| --- | --- | --- |
| 전력 운용·터렛 ON/OFF | 필드·해당 Stage | 영구 능력치 성장과 구분 |
| 자동 활성화·전술 지도·원격 터렛 작동 | CU에서 제공. 원격 작동은 **점유된 땅**에 한정 | 권한·정보·UI 상세 |
| 무기 선택·교체 | 필드 행동으로 정리 | 인벤토리·소지 개수·교체 방식 |
| Player·무기 업그레이드 | 우주선에서 전역 성장 | 화면·비용·저장 계약 |
| 터렛·CU 능력치 업그레이드 | 현장에서도 전역 유지, 우주선에서도 가능하게 하는 안 포함 | 최초 제공 범위와 CU 성장에 따른 편의 해금 순서 |
| 개별 터렛 승급 | 플레이어가 터렛에 직접 접근해 적용 | 권한 획득 장소: 수기는 우주선, 녹음은 CU 또는 우주선이라는 표현. 실제 승급 장소와 구분해 확인 |

전술 지도에는 전선·강약 정보를 주고, 해금/점유 경계는 화면에서 분명히 보이게 하자는 요구가 있었다. 선·색·외곽 표현은 후보이며 내부 사각 Grid를 그대로 그려야 한다는 결정은 아니다. 시작 구역 제한·튜토리얼 후 확장도 제안이다. [00:28:02–00:35:15]

우주선 안에서도 필드를 진행하던 기존 구상에서 **진입하면 정지하는 방향**으로 재논의했다. 필드 CU 업그레이드와 같은 조건으로 묶지 않았다. 당시 정지 범위·시간대·복귀 처리는 남았고, 다음 날 몬스터·터렛까지 멈추는 방향을 재확인했다. [00:40:29–00:42:56, 01:39:58–01:42:35]

## 4. 왕복 편의·정비·재미 검증

[00:44:07–00:58:19, 01:54:22–01:56:04]

- 업그레이드마다 우주선을 왕복하는 번거로움과 필드 기능이 많아 우주선에 갈 이유가 줄어드는 문제를 함께 검토했다.
- 우주선 호출, 지정 착륙 지점, 귀환/텔레포트, 비전투 제한·긴 쿨타임은 제안이다. CU 내부에 모든 기능을 넣는 대안도 최종 채택하지 않았다.
- **기존 흐름을 먼저 만들고 실제로 시험한 뒤 편의 기능 필요성을 판단**하기로 했다. 신규 호출·귀환 시스템을 필수 Backlog로 확장하지 않는다.
- 소강 상태와 대사·스토리로 정비 타이밍을 안내하자는 아이디어를 명시적인 Wave UI 재도입 결정으로 바꾸지 않는다.
- 기능 추가로 변수를 늘리기 전에 핵심 재미 검증을 서둘러야 한다는 의견을 우선순위로 남긴다. M1/M2 Gate나 팀 공통 Build 통과를 선언하지 않는다.

## 5. 날씨·밤·맵 기믹

[01:23:06–01:56:04]

맵 고유 기믹의 구체화는 뒤로 미루고 날씨를 우선 논의했다. 맵 기믹 전체 영구 폐기나 채집 기능 신규 도입으로 해석하지 않는다.

| 제안자 | 후보 | 미정·주의 |
| --- | --- | --- |
| 이영빈 | 폭염 때 터렛 과열이 빨라짐 | 구체 효과는 수기에 명시. 연출은 녹음에서도 논의. 속성·수치 미정 |
| 양현석 | 시간대 변경 시 가중 랜덤 날씨. 안개 사거리 저하, 비/눈 냉각 속도 증가, 폭풍 스폰 주기 변화·명중률 저하, 흐림 스폰 주기 변화, 맑음 기본 | 원표현 “스폰 주기 증가”를 간격/빈도 중 하나로 임의 해석하지 않음. 전환·가중치·행성별 목록 미정 |
| 김진태 | 번개가 터렛/CU에 전력 혜택 또는 HP 피해, Player에는 HP 피해 | 현재 Shader 표현과 향후 오브젝트 상호작용을 구분. 채택·대상·확률·지속 시간·구현 방식 미정 |
| 황재동 | 밤에 강한 적과 높은 위험/보상, 우주선 정비 권장 | 구체 난도·보상·시간·방어선 생존은 미정 |
| 조수빈 | 밤 암살자 증가와 Player 추적, 태양열 설정으로 총 전력 감소, Player에 이로운 효과 | 추가 제안. 전력 감소에는 선호 차이가 있었으며 스폰·전력 수치 미정 |

무제한 전력 이벤트를 채택한다면 종료 시 **자동 활성화로 fallback**하는 방향은 녹음과 수기가 일치한다. 이벤트 자체의 확정·구현 완료는 아니다. “다음 주까지 가능한가”라는 질문을 확정 마감으로 옮기지 않는다. [01:42:51–01:46:13]

후반에는 기존 낮밤·강수·번개 표현에 **더위 표현 정도를 보강하고 시험하면서 덜어내자**고 범위를 좁혔다. 모든 후보 효과·날씨 개수를 일괄 확정하지 않는다. NPC/AI 안내·대사·시네마틱도 설명 방식 후보이며 채택 UX가 아니다.

## 7. 근거의 한계

다섯 AAC 전체를 로컬 자동 전사하고 주요 10구간을 같은 small 모델로 재전사했다. 이는 직접 청취·독립 검증이 아니다. 힌트 반복 의심 용어 목록은 원인식/대조 결과와 함께 보존하고 결정 근거에서 제외했다. “지금 11월 1일”이라는 발언은 녹음 메타데이터의 10월 30일과 충돌하므로 회의 날짜나 마감으로 사용하지 않는다. 확정 수치·저장 계약·API·멀티플레이 정지·완료 증거는 추가 검증이 필요하다.
