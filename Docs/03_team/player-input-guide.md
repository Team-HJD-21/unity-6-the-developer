# Player V2 조작 및 연결 안내

수정일: 2026-11-09

| 입력 | 동작 |
| --- | --- |
| WASD / 방향키 / 게임패드 왼쪽 스틱 | 이동 |
| 마우스 | 조준 |
| LMB 유지 | 장착한 무기로 공격 |
| LMB 클릭 | UI 조작 / 설치 확정 / 포탑 선택 (해당 문맥 우선) |
| Space 한 번 | 이동 방향으로 짧게 대시. 정지 중에는 마지막 이동 방향 사용 |
| 1 / 2 / 3 / 4 (숫자패드 포함) | 스패너 / 기본총 / 냉각총 / 스나이퍼 직접 선택 |
| 마우스 휠 아래 / 위 | 다음 / 이전 무기 |
| Tab | 다음 무기 |
| 하단 무기 슬롯 클릭 | 해당 무기 선택 |
| Q / E | 슬롯에 선택한 스킬 사용 |
| F | 가까운 본인 소유 플레이어 터렛 회수 |
| R 유지 | 가까운 일반 필드 터렛 수리·파괴 복구. 초당 10%, 이동하면 취소 |
| 우클릭 | 방벽의 미완성 첫 펄스 취소 |
| Escape | 열린 스킬 선택창 닫기 |

`GameInput`은 장치 입력을 읽고, `PlayerInputHandler`는 플레이어 조준 방향과 프레임별 입력을 수집한다. 실제 스킬 실행과 선택은 `PlayerSkillController`, 공통 사용 조건은 `PlayerSkillBase`가 담당한다. UI는 개별 View 클래스로 나뉜다.

무기는 1~4 슬롯 순서로 순환하고 양 끝에서 이어진다. 최초 장착은 기존 기본총(2번)이다. 장비가 없는 슬롯은 건너뛰며 일시정지·조작 차단·스킬 선택 중에는 전환하지 않는다. UI 위의 휠은 무기 전환에서 제외하고, 테스트 카메라 속도 조절은 Shift+휠을 사용한다. 숫자키·휠·Tab이 동시에 입력되면 이 순서로 하나만 처리한다.

스나이퍼는 확산 없는 단발이며 공격 입력은 LMB다. 냉각총·스나이퍼는 몸체와 분리된 외형 데이터를 사용한다. 무기 전환은 남은 공격 대기시간을 초기화하지 않는다. Space는 대시에 사용하며 유지해도 자동 반복하지 않는다.

대시는 Q/E 선택 스킬과 분리된 이동 능력이다. 초기 설정은 속도 2.5배·0.16초·쿨타임 1.2초다. 이동 입력이 한 번도 없으면 정지 대시는 아래 방향을 사용한다. 대시 중 조준·공격·무기 전환은 유지하고, 조작 차단·일시정지·스킬 선택·설치 문맥에서는 중단한다. 짧은 잔상 4개를 Player 프리팹에 미리 배치해 재사용한다. 하단 무기 선택창 오른쪽의 Space 표시에서 재사용 대기를 확인한다. 테스트 카메라 줌은 PageUp/PageDown이다. [대시 API와 편집 위치](../02_architecture/06_player/player-dash-api.md)

클릭은 **UI → 설치 → 포탑 선택 → 공격** 순서로 처리한다. UI 클릭, 설치 성공·실패 및 먼 포탑·이미 선택한 포탑의 클릭은 공격으로 이어지지 않는다. UI를 벗어나거나 설치가 끝나도 누르고 있던 버튼으로 공격을 시작하지 않으며 놓고 다시 눌러야 한다. 공격 중 UI 위로 이동하거나 일시정지·조작 차단·스킬 선택이 발생한 경우도 같다.

빈 지면 클릭은 포탑 선택을 해제하고 일반 공격에 사용할 수 있다. 스패너도 같은 우선순위를 따르므로 포탑을 직접 클릭하면 먼저 선택한다. 방벽의 두 번째 본체도 LMB로 확정하며 미리보기 중 LMB 공격은 차단한다. 상세 API와 검증 경계는 [클릭 입력 분리](../02_architecture/06_player/player-primary-input-api.md)를 참고한다.

일반 필드 터렛 수리·복구는 발 위치 기준 XY 반경 3 안의 터렛 아래에 뜨는 R 안내를 보고 키를 유지한다. 체력이 남아 있으면 최대 체력의 10%/초를 회복한다. HP 0은 주황색 복구 게이지가 초당 10%씩 증가하고, 100%에서 최대 체력·OFF 상태로 복구된다. 완료 전에는 켤 수 없고 완료 후 기존 켜기 조작이 필요하다. 수리·복구 중에는 몸과 무기가 작업 터렛을 향하며 일반 스패너 공격 모션을 반복하고 실제 공격은 중단한다. 끝나거나 취소되면 마우스 방향을 다시 따른다. 이동 입력·밀려남·대시·거리 이탈·조작 차단·설치 미리보기로 취소되면 R을 놓고 다시 눌러야 한다. 중단된 파괴 복구 게이지는 같은 터렛에 유지되며, 완전히 회복한 대상에서 다른 대상으로 자동 전환하지 않는다. 플레이어 스킬 터렛 수리는 별도이며 F 회수 동작은 유지한다. [수리 API와 프리팹 편집 위치](../02_architecture/06_player/player-weapon-api.md#포탑-수리)

조작 잠금은 `PlayerControlState.SetInputBlocked`로 전달한다. Match를 소유한 Scene은 `PlayerSceneAdapter.Bind`를 통해 `IPlayerMatchBinding` 구현체에 현재 Match를 연결하고, 종료할 때 `Unbind`한다. 연결 해제된 플레이어는 조작할 수 없다. 플레이어 사망은 `PlayerInfo.onDeath` 이벤트로 전달하며 기존 씬에서는 `InGameManager`가 구독한다. Player V2 코드에서 해당 매니저를 검색하지 않는다.

현재 PoC 설정은 준비 중 행동과 전투 중 스킬 선택을 허용한다. 정식 단계별 제한을 적용할 때 `PlayerControlState`의 `_allowActionsDuringPreparation`, `_allowSelectionDuringCombat` 설정을 끈다. 기존 Scene의 상태 공급 함수는 Match가 연결되지 않은 경우에만 사용한다.

플레이어 터렛은 처음 3개를 보유하고 설치 간격은 3초다. `Assets/Prefabs/Player/PlayerTurret.prefab`의 `PlayerTurretHealth`에서 체력 100과 충돌 반경을 조절한다. 회수 시 충전 시간은 `(1 - 현재 체력 / 최대 체력) × 최대 충전 시간`이다. 손상 없는 포탑은 즉시 반환되고, 절반 손상은 15초, 파괴는 30초 후 반환된다. 각 포탑은 독립적으로 충전된다. 최대 충전 시간은 Player 프리팹의 `PlayerTurretSkill._maximumRepairSeconds`에서 변경한다. 설치 쿨타임과 충전은 별도로 진행된다.

피격 표시는 색상 틴트만 사용한다. 추가 파편, 섬광, 흔들림과 체력바는 추가하지 않는다. 신규 네트워크 적은 스킬 측 중재 컴포넌트로 연결하며 몬스터 원본은 변경하지 않는다. 장비 자체의 네트워크 Spawn과 클라이언트 설치 요청은 후속 작업이다.
