# Stage 1 최대 전력 500 고정 검토

PR: [#736](https://github.com/Team-HJD-21/unity-6-the-developer/pull/736)

## 바꾼 이유

Stage_1 제작값은 1000, Initial_Stage는 100이고 성장 저장의 용량도 복원돼 시험 기준이 달랐다. 이번 시험은 두 씬 모두 최대 500으로 고정한다. 가용 전력은 터렛 가동에 따라 줄어들며 항상 500을 유지하는 값이 아니다.

## 먼저 볼 파일과 흐름

1. `FieldTurretController.cs`: `fixedMaximumPower`가 양수이면 최초 예산을 이 값으로 만든다. `TrySetMaximumPower`로 다른 값을 적용하는 요청은 거절한다. 0인 다른 씬은 기존 정책이다.
2. `FieldTurretController.Growth.cs`: 과거 성장의 용량보다 Scene의 고정값을 우선한다. 레벨·강화·DamageBonus는 보존하며 기존 `MergeGrowth`로 예약을 재계산한다. 전력이 부족한 복원 대상은 OFF와 이유 표시를 사용한다.
3. `FieldTurretController.Checkpoint.cs`: 재조정하지 않은 다른 용량을 내부 적용하지 못하게 검증한다. 월드 복원은 기존처럼 최신 성장/현재 용량과 합친 뒤 이 경계를 지난다.
4. `Stage_1.unity`, `Initial_Stage.unity`: 각 Controller의 `maximumPower`와 `fixedMaximumPower`만 500으로 변경했다. 오브젝트·지형·터렛 배치·GUID는 바꾸지 않는다.

## 확인

Unity CLI EditMode의 `FieldTurretRestoreVisualTests` 7/7 통과. 실제 제작 Canon/Missile와 writer를 사용해 과거 100/1000 성장·월드 복원 후 최대 500, 예약/가용 전력, 공격력 강화 유지와 기존 표시 복원을 확인했다. 고정 해제 시 원래 성장 용량 복원도 유지한다. [검사 요약](evidence/fixed-power500-20261115.json)

테스트는 예외·경계 확인용이므로 주 실행 흐름을 읽을 때 생략해도 된다. 전체 자연 전투 밸런스와 Windows 빌드는 이번 검증에 포함하지 않는다. 실제 전체 월드 저장은 별도 Weather writer가 없어 계속 차단된다.

## 담당과 되돌리기

Core/FieldTurret 연결 변경이다. HP·공격·과열·업그레이드 규칙과 Player/Enemy 코드는 바꾸지 않았다. 시험 고정을 해제하려면 Scene의 `fixedMaximumPower`를 0으로 되돌린다. 저장 파일은 삭제하지 않는다. 전력 500에서는 기본 배치 전체 필요량 550보다 50이 부족하다.
