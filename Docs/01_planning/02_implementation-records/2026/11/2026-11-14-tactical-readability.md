# 전술 지도 상태·가독성 후속 수정

2026-11-14. 이전 전술 UI 마감 이후 사용자가 요청한 입력·실제 정보·시인성 수정이다. 이전 검수 결과를 이번 수정의 통과로 합치지 않는다.

## 반영 범위

| 요청 | 구현 접점과 표시 |
| --- | --- |
| 일반 지도처럼 이동 | 우클릭/가운데 드래그로 카메라 이동. 우클릭이 드래그로 시작되면 핑을 남기지 않는다. viewport 실제 픽셀 높이와 현재 배율로 이동량을 환산하고 기존 Smoothstep·경계 제한을 유지한다 |
| 실제 전선 | 현재 Match의 `BattlefieldSpatialSnapshot.FrontlineEdges`와 원본 정점 좌표를 읽는다. 점유 셀 외곽과 다른 옅은 청록색 선이며 UI가 삼각형/전선을 재계산하지 않는다 |
| 점유 구분 | 확정 점유, 해금된 점유 가능, 실제 누적이 있는 점유 중, 미점유/미해금. 지도 위 채움·테두리·사선 패턴으로 구분하고 상시 문장 범례를 두지 않는다. 점유 진행 링과 보류 심볼은 실제 Host 진행 표본이다 |
| 사거리 | 기본 가동 중 전체. 지도 설정에서 선택한 터렛만으로 전환한다. 냉각 중 활성 상태를 OFF로 오해하지 않으며 선택한 비가동 터렛의 범위도 확인할 수 있다 |
| 터렛 상태 | 가동·대기·잠금·냉각·전력 부족·파괴·조작 대기·미준비를 전원/잠금/시계/전력/X/일시정지 형태와 의미색으로 구분한다. tooltip·선택 도크도 같은 상태 분류를 사용한다 |
| 근접 F | 구조 대상 → 플레이어 설치 포탑 회수 → 가까운 필드 터렛 토글 우선순위. 동일 입력으로 회수와 토글을 동시에 실행하지 않는다. 필드 터렛은 포인터가 다른 곳이어도 가까운 대상을 선택한다 |
| 지도 버튼 | 우하단에 지도 심볼+`전술 지도`. M 입력은 유지하고 버튼의 M 중복 문구는 제거한다 |
| 먼 적 | 기존 LOD 기준에서 작은 붉은 점을 실제 위치에 표시하고 별도 원본 무리 심볼·실제 합계 수량으로 밀집 정보를 보강한다 |
| 필드 핑 | 우클릭 목표가 지도 닫기 후에도 유지된다. 화면 안 beacon/밖 방향·거리는 같은 목표 좌표를 읽는다. HP·상단 시간·하단 스킬/무기 안전 영역을 확보하고 접근 시 해제, 전체도 헤더의 목표 해제 아이콘을 제공한다 |
| 지도 설정 | 전체도 패널 안에 사거리·지형지물을 묶고 목표 해제는 같은 패널의 헤더에 둔다. 사거리와 지형 선택은 로컬 PlayerPrefs에 저장한다 |
| 지형지물 숨김 | Scene 명시 참조 `Environment_Obj` TilemapRenderer만 전술 중 `forceRenderingOff` 처리한다. 원래 렌더 상태를 닫기/disable/파괴 때 복원한다. 지면·물·충돌·활성 상태와 터렛/Player/Enemy 본체는 바꾸지 않는다 |

편집 접점은 [Player UI API](../../../../02_architecture/06_player/player-ui-api.md#2026-11-13-전술-화면), 디자인은 [공통 규칙](../../../../94_art/common-ui-rules.md), 에셋은 [전술 제작 규칙](../../../../94_art/tactical-ui-assets-2026-11-14.md)을 따른다. 프리팹·설정의 기존 GUID를 유지한다. Stage_1 저장 변경은 장식 renderer 배열 크기와 요소 참조 두 override뿐이다.

## 데이터 경계

전선과 정적 확보 진행은 현재 Host에 읽기 원본이 있다. Client의 지역/터렛 확정 replica에는 전선·확보 중 타이머가 포함돼 있지 않다. Client의 미수신을 임의 전선이나 가짜 누적 시간으로 채우지 않는다. Client 진행 표시를 확장하려면 기존 지역 revision과 별도로 갱신되는 진행 표본의 발행 주기·Match/Grid 세대 검증이 필요하다. UI가 점유 완료나 해금을 확정하지 않는다.

터렛 본체 tint/Heat Wave는 이 수정 범위가 아니다. 새 상태색은 UGUI 아이콘·배지에만 적용한다. 병행 Core 세션이 본체 효과의 main 원본과 실제 잠금 상태를 별도로 조사한다.

## 추가 시인성 수정

플레이어/CU/이전 시야는 전체도 헤더의 같은 크기 아이콘 버튼이다. 닫기48×40과 설정48×40은 화면 오른쪽 끝 독립 열에 두어 전체도와 겹치지 않게 한다. CU 자동/다중/일괄 조작도 기존 제작 glyph를 사용한다. 버튼 이름은 0.35초 hover 때만 공통 카드로 표시한다. 상시 범례·정상 상태의 떠 있는 ‘가동’ 문구를 제거한다.

선택 시설/필드 hover/위협 카드의 HP는 분할 게이지다. 전력·적 수량은 해당 심볼 옆의 실제 수치만 표시한다. 다중 선택의 위협 수량은 각 사거리의 합집합에서 세어 같은 적을 중복 합산하지 않는다. 월드 아이콘은 서로 다른 상태 배지를 유지하며 피해/선택/체력 손실 때 HP 게이지를 표시한다. Player/CU에는 실제 생존 원본 또는 Host 확정 CU 체력을 사용한다.

같은 최대 HP에서 실제 체력이 감소하면 해당 터렛 아이콘·상태 배지·위협 카드가 0.42초 감쇠 진동한다. 카메라나 사거리 원본 좌표는 흔들지 않는다. 감소 전 HP는 0.18초 유지 후 0.65초 Smoothstep으로 줄고 연속 피해는 남은 잔상을 보존한다. 첫 연결·최대 HP 변경·회복은 새 피격으로 만들지 않는다. 사건 목록은 실제 피격 우선, 비가동 터렛의 실제 사거리 내 적으로 구성하며 클릭 시 해당 터렛으로 시야 이동한다.

사용자 제공 육각 격자 레퍼런스는 후속 구현 승인을 받아 이번 범위에 포함했다. `TacticalModeFrame.shader/.mat`와 `TacticalModeEffect`로 진입0.22초/종료0.14초를 표시한다. 중앙을 덮는 RGB 분리/왜곡/블러는 없고 유지 중 가장자리의 낮은 대비 망만 남는다. Overlay Canvas(-900)로 기존 HUD/전술 조작 패널보다 먼저 그려 작은 표식·HP의 가독성을 보존한다. `raycastTarget=false`이며 카메라/조작 lease는 시각 효과를 기다리지 않는다. 빠른 재진입은 현재 진행값에서 이어진다. Material은 로컬 복제 후 해제하며 색·셀 간격·폭과 프리팹의 시간을 에디터에서 편집한다.

전체 축소 실화면에서 적 수량이 터렛 도상을 가린 사례를 발견해 가까운 빈 위치를 찾도록 보정했다. 터렛 상태/HP와 Player/CU, 패널/Alert, 이미 놓은 수량 표식도 피한다. 빈 위치가 없으면 수량 카드만 생략하고 실제 적 점은 유지한다.

## 검증 상태

Unity6000.3.23f1 DX11 / Input System1.17 / URP17.3의 실제 Stage_1에서 확인했다.

- Unity 소스 컴파일 성공, 실제 Material의 `ShaderHasError=false`.
- `StageTurretCommandHudTests`8/8 최종 통과90.17초. 실제 Host F/활성화·강화/자동 처리/재구독, 메뉴·스킬, 우클릭 드래그의 핑 누출 방지, renderer/collider 보존, 핑 유지, Smoothstep/클램프, 실제 피해의 흔들림·HP 잔상, 닫기/전체도 겹침, 전환 시작/종료를 포함한다.
- `Tactical` 필터16/16 통과13.06초. Scene 항목1개가 위와 중복이므로 합계는 **고유23개**다. 상태/전력 경계·실제 점유 진행·다양한 화면비의 카메라 경계·제작 참조·피격 표본·GPU 중앙 alpha0/실제 테두리 출력을 포함한다.
- 정상 Play 캡처에서 진입/유지/피격/설정/종료/필드 핑/전체 지도/아이콘 hover를 검토했다. 실제 피해100→75에서 게이지0.75·감소 잔상1.0·짧은 아이콘 변위를 계측했다. 빠른 닫기/재진입의 진행값 연속=true, 완전 종료 progress0/surface disabled를 확인했다.
- 전체 지도 실제 viewport와 경계는 모두(-138,-120,276,240)이다. 먼 터렛12개와 여러 회차의 적55~72개에 대한 glyph/붉은 점·실제 수량 표현을 확인했다. 전선은 Host 원본이며 UI가 전선을 재계산하지 않는다.
- 제작 중 지도 설정의 빈 Image가 상태 도상을 덮은 것을 실제 캡처에서 발견해 제거했다. 수정 뒤 설정 심볼을 다시 검토했다. 전체도와 닫기/설정의 실제 사각형은 회귀 검사에서 겹치지 않았다.
- 저장소의 `validate_meta.py` 검사0오류, 새 에셋9개의 대응 meta/참조를 확인했다. 문서 상대 링크와 작업 범위 diff whitespace 검사도 통과했다.
- 기존 스테이징8개 binary diff가 동일하며 폰트4개의 원래 문자23/11/211/1은 모두 보존했다. Scene 저장 diff는 장식 renderer 배열/요소 두 override뿐이다. 다른 파트의 Core/Enemy prefab·Rendering 설정과 Core 세션의 restore tint/test 수정은 포함하거나 덮어쓰지 않았다.

중간 실패도 최종 결과와 구분해 보관했다. 첫 Scene 토글 fixture가 비활성 버튼에서 실패했고, 다른 Scene 검사와 동일하게 Player/CU QA 보호를 둔 뒤8/8을 확인했다. 별도 한 회차는 bootstrap의 null/Netcode 종료 예외가 있었고, 같은 구간에 프리팹 정규화/import가 겹쳤다. 원인을 확정하지 않았으며 모든 import가 끝난 안정 상태에서 소스 변경 없이16/16을 다시 확인했다. 이 실패를 통과로 숨기거나 새 제품 결함의 근거로 단정하지 않는다.

native 근거는11~19번 PNG/JSON이다. 실제 ON/OFF 스냅샷과 빨강/초록 label, CU/이전 시야 좌표 왕복, 설정 false/false→true/true, 필드 goal 유지/effect0, 선택 null·가동1기·전체 사거리=true를 기록했다.

캡처·개별 결과·실패 이력·에셋 감사는 공유 제외 `Docs/Local/Validation/Tactical20261114Revision`에 있다. `ScreenCapture`는 실제 합성 Game View를 캡처하며 카메라 단독 렌더를 HUD 검수로 대신하지 않는다. QA의 위치 이동/보호/직접 피해는 Play 전용이고 종료 때 사라진다. 최종 키보드·held drag 하드웨어 인수는 사용자에게 남긴 기존 범위다. 컴퓨터 유즈는 물리 Escape 중단 응답 뒤 입력을 멈췄다. 다음 목표 턴에서 JavaScript kernel을 새로 열고 공식 sky import→반환된 Unity 창 재선택으로 연결이 회복됐다. 이후 native 마우스로 지도 열기/닫기, 플레이어 아이콘 hover 이름, CU/이전 시야, 사거리/지형지물 두 설정 왕복, 우클릭 목표/필드 유지, 필드 정보 카드, 터렛 선택/ON/OFF와 hover 상태색, 선택 해제 후 가동 사거리, 실제 휠 축소를 확인했다. 설정은 처음 값으로 복원했고 Play를 종료했다. 같은 결과를 UI callback 호출만으로 대체하지 않았다. 키보드·held drag의 최종 하드웨어 인수는 사용자 범위다.

현재 Client에 없는 전선/정적 확보 진행의 복제 계약과 standalone Player 빌드는 이번 검증에 포함하지 않았다. 새 커밋·푸시·PR은 수행하지 않았다.

## 이후 사용자 재요청

전체 덮임/중앙 파동/완료 시 UI 교체·연속 영역·필드 확보/이탈 표시는 [후속 기록](2026-11-14-tactical-wave-and-territory.md)을 우선한다. 위 검증 결과는 이전 단계의 기록으로 보존한다.
