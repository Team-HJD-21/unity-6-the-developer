# 낮밤 주기와 Steam SDK 연동 배치

기준: `ded96c144` 이후 현재 Core 작업 브랜치. PR/push/merge는 하지 않는다.

## 수정 전에 정한 진태님 작업 경계

- 내가 새로 만드는 것: Core 공용 시계 기반 낮300초/밤300초, Host의 전환 신호, 환경 snapshot/Client 읽기/낮밤 section 저장, App 소유 Steam SDK 초기화·식별·콜백·종료와 로비 API.
- 접점 수정: `Map/WeatherManager.Core.cs`에서 낮밤 전환을 받도록 연결한다. 같은 객체에 낮밤 주기가 있으면 CountTick의 독립 날씨 예약은 등록하지 않는다. 다른 독립 Scene의 기존 CountTick 호환 경로는 유지한다.
- 건드리지 않는 것: `WeatherManager.cs`의 GetWeather/예고 큐/가중치, 셰이더·날씨 효과, 진태님 고유 Weather writer, 실제 포털/콘솔. 낮밤의 저장과 Weather의 실제 날씨/큐 저장은 별개다.
- 낮밤 전환 자체가 Encounter를 생성하지 않는다. 확정된 환경을 다음 요청의 계획 조건으로 전달한다. 실제 낮밤 조명/연출의 새 디자인은 만들지 않는다.

## PL이 준비할 것

실제 게임 AppID, 서로 다른 테스트 Steam 계정의 해당 앱 실행 권한. 내부 계정은 Dev Comp, 외부 테스트는 Release Override 등의 방식을 사용한다. 출시를 먼저 할 필요는 없다. SDK 초기화·로비와 운영 Backend 재화/프로필 인증은 분리한다. 실제 계정/인터넷 인수가 안 된 상태는 명확히 남긴다.

## 기존 전달본과 달라진 Weather 저장 안내

낮밤 주기를 사용하는 Initial_Stage에서는 CountTick이 예약을 소유하지 않는다. 진태님의 `world/weather` writer는 현재 날씨/예고 큐/난수 상태를 보관하고, **낮밤의 남은 시간·구간 설정은 Core `world/time-of-day`가 담당**한다. 따라서 이 모드에서는 CountTick.CaptureTimerState/RestoreTimerState를 호출하지 않는다. 낮밤 없는 기존 독립 Scene에서만 CountTick 방식이 유지된다. 이 변경은 진태님의 실제 writer를 수정하기 전에 전달 문서에 먼저 명시한다.

## 수동 확인 최소화 추가

Startup→우주선 카메라/실제 Player 생성·이동·GPU 월드 렌더·왕복, 낮밤/정지·Weather 단일 전환, 기존 파일 복원/취소·CU 종료/새 판, 가능한 두 프로세스 경로를 직접 검사한다. PL에게 자동화 가능한 기능 확인을 다시 넘기지 않는다. 시각적 가독성/조작감·실계정 권한 등 남는 인수만 최종 보고에 분리한다.

## 추가 승인 — 레거시 형식 로딩

전체 검은 배경과 하단 진행 바만 표시한다. 로딩 카드/제목/설명/취소 버튼은 제거한다. Scene 로드에서 Mission 준비 완료까지 유지하고, 실제 진행률이 없는 네트워크 대기는 이동하는 막대로 구분한다. 실제 GPU 캡처와 입력 잠금/정리 검사를 포함한다.
